# Product Backlog - StudyLink

**Estimated using story points (Fibonacci: 1, 2, 3, 5, 8)**  
**Aligned with Use Case Diagram & Team's Sprint Planning Notes**

1. As a user (freshman or senior), I want to register and login with my Taylor's student email so that my identity is verified and my tutoring history is tracked securely. (Points: 3, Priority: High)  
   → Covers "Register / Login" use case for all actors; ensures only Taylor's students can access the platform.

2. As a freshman, I want to create a tutoring request post with subject code (e.g., ITS6102), topic (e.g., UML Use Case Diagram), detailed description of my confusion, and preferred time slot so that seniors can understand my need clearly and respond quickly. (Points: 5, High)  
   → Covers "Post Tutoring Request"; includes real course examples from our team's interviews.

3. As a senior student, I want to browse all open public tutoring requests, sorted by subject, time, or most recent, so that I can quickly find ones I can help with based on my expertise and schedule. (Points: 3, High)  
   → Covers "View Public Requests"; sorting options are based on feedback from senior tutors we spoke to.

4. As a senior, I want to assign myself to a specific tutoring request, so that the freshman sees my name and contact info, and we can coordinate the tutoring session. (Points: 5, High)  
   → Covers "Assign Self to Request"; we added contact info visibility to make coordination easier.

5. As a freshman, I want to view the status of my posted requests (open, assigned, in progress, completed) and see assigned tutor details (name, contact, subject expertise) so that I know who is helping me and when. (Points: 3, Medium)  
   → Covers "View Assigned Tutor"; added expertise info to help freshmen feel more confident.

6. As a tutor (senior), I want to update the status of an assigned request (e.g., "In Progress", "Completed") so that the board and freshman stay informed about the tutoring process. (Points: 3, Medium)  
   → Covers "Update Request Status"; status options were chosen to reflect real-world tutoring workflows.

7. As a user, I want to view my personal tutoring history (requests I posted or tutored) so that I can track my participation and contributions to the community. (Points: 2, Low)  
   → Added to encourage long-term engagement and recognize peer contributions.

8. As a user, I want to logout securely so that my session ends safely, especially when using shared campus computers. (Points: 1, Low)  
   → Addresses a security concern raised by our team during risk assessment.

9. As an admin, I want to manage users (view, suspend, or delete accounts) so that the platform remains safe and free of misuse, such as spam or inappropriate requests. (Points: 5, Medium)  
   → Added to support platform governance; aligns with our UML "Manage Users" actor.

**Total estimated points**: 30  
**Notes**:  
- Acceptance criteria and detailed tasks will be broken down in Trello cards during sprint planning, using our team's agreed-upon definition of "done".  
- Backlog prioritized based on core flows from Use Case Diagram (freshman post → senior assign → status update → view), which we identified as critical for MVP.  
- Optional admin features can be deprioritized if time is limited, as our initial focus is on peer-to-peer functionality.
